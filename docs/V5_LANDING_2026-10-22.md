> 冷启动/写锁/预算），见 [`V5_1_LANDING.md`](V5_1_LANDING.md)；本文件保留 v5.0 的原始落地记录。

> 设计细节见 [`V5_ACTIVITY_RUNS.md`](V5_ACTIVITY_RUNS.md)，契约见 `CONTRACT.md`。

## 0. 一句话

把 FGS 从「单会话按图切角色」改成 **kernel + 一次性活动 run**：一道题 = 一串干净的
Decide / Execute 进程，每轮只做一件事，退出即销毁上下文，唯一共享记忆是图。
kernel（GraphStore / Controller / ops / hooks / FLAG 门 / 图格式）**一行没动**。

### 1.4 活动协议（环境变量）

| 变量 | 值 | 含义 |
|---|---|---|
| `FGS_ACTIVITY` | `decide` \| `execute` | 本 run 只做这一个活动；未设 = 旧单会话模式 |
| `FGS_STEP` | `step_003` | Execute 要推进的 step；插件启动时直接认领 |
| `FGS_RUN_ID` | `demo-01-execute` | **owner 就是它**（不是会话 id）；台账对齐用 |
| `FGS_LEASE_MS` | `750000` | 认领租约；选择器与插件必须同值 |

### 1.5 关键语义（本次确定）

- **工具在注册期隔离**：Decide 只注册 11 个图工具；Execute 只注册
  `fgs_status / fgs_preview / fgs_submit_fact / fgs_commit_step`。越权工具在 schema 层不存在。
- **无身份认领**：`owner = runId`；`refreshRole()` 在活动模式下不再由图现算。
- **Decide 不认领它开的 step**（本次真实 host 冒烟抓到的 bug，见 §3）。
- **Execute 收束后**任何非 `fgs_*` 工具被 guard 拒（防止拿完 flag 继续乱逛）。
- **不空转**：图签名未变 → 直接 `defer`，并写 `meta.state=deferred`。
- **超时**：编排器先 SIGTERM（插件信号兜底写中断 Fact），宽限后 SIGKILL；整题继续。
- **死 run 回收**：`release_step` 追加未完成 Fact、owner 清回 null、step 保持 open。
- **台账**：`.fgs/projects/<id>/activity.jsonl`（插件）、`.fgs/orchestrator.jsonl`（编排器）、
  `.fgs/orchestrator-exit.json`（退出摘要）。

## 3. 本次修掉的 bug（都有回归测试）

1. **活动 Decide 会认领它打开的 step**（真实 host 冒烟发现）：`fgs_commit` 的
   `claimOpened` 默认 true，decide run 结束就退出，step 被锁在租约里，Execute 判成
   「被别人持有」。现在活动模式强制不认领。
2. **选择器与插件的租约不一致**：会出现「选择器说可接手、插件说被持有」的僵局；
   现在编排器统一传 `FGS_LEASE_MS`，并作为 CLI 的 `--lease-ms`。
3. **死 run 的认领无人回收**：SIGKILL 后 step 永远 owner=死 runId，整题空等。
   现在编排器用 `release_step` 精确回收（幂等）。
4. **turn-stopping 会替没进 FGS 的会话建 run / 抢 step**：改为只对已存在的 run 收口。
5. **`autoAttach: false` 会让活动 run 一律「未启动」**：活动模式绕过该开关（run 本来就由编排器起）。
6. **注入上下文用 `run.sid` 与会话 id 比对**：owner=runId 后会误判；活动模式改判。
7. **代次断言固定在 13**：升级到 14 时更新（schema_ux / v3 / v4 对抗测试）。

## 5. 已知限制

- **活动模式串行**：一道题一次只跑一个活动；多 Execute 并行还没开（需要跨进程写锁）。
- **真实模型 E2E 未跑通**：`tests/fixtures/fake_llm.py` 在工具结果回灌上会重复调用；
  真实 key 的一次冒烟待做。
- **deferred 不重试**：`defer` = worker 退出，靠 driver 下一次 visit，没有进程内 retry。
- **Decide 进程仍有世界工具**：guard 会拒绝，但 schema 仍可见（提示词污染）；
  彻底隔离需要独立 decide profile/patch。
- **pnpm 记账未刷新**：`pnpm-lock.yaml` / `.package-map.json` 仍含旧包名；
  下次 `dsh plugin` 安装会自动 reconcile，不影响运行。

## 6. 后续建议（按优先级）

### P0 — 直接影响比赛成绩

1. **真实模型 E2E 冒烟（一次就够）**：用真实 key 跑
   `FGS_ACTIVITY=decide` 与 `FGS_ACTIVITY=execute` 各一次，确认：
   模型能按「结束信号」停、`fgs_commit_step` 落盘、台账 `outcome=committed`；
   顺便验证网关的 `function_call`（必须 openai-completions）。
2. **重建竞赛镜像并端到端验证**：镜像里装 `@local/fgs-v5-dsh`、带 `headless` profile、
   `CONTEST_DSH_LAUNCH=1`；跑一次 `entrypoint.sh` → driver → activity_loop → dsh 的完整链路；
   确认镜像 <3GB、无公网依赖、SIGTERM 下能收束。
3. **把活动参数暴露给 driver**：目前 `activity_loop.py` 的
   `--activity-timeout-sec / --max-activities / --budget-sec` 只能手工传；建议
   driver 支持 `CONTEST_ACTIVITY_TIMEOUT / CONTEST_MAX_ACTIVITIES / CONTEST_ACTIVITY_BUDGET`
   环境变量并在 `launch_dsh` 里透传，方便按题难度调参。
4. **超时/被杀路径压测**：对 activity loop 注入 SIGTERM/SIGKILL，确认
   `orchestrator.jsonl.released`、未完成 Fact、`defer` 三种收尾都正确。

### P1 — 架构与质量

5. **跨进程写锁**：给 Controller 的 `load → apply → commit` 加文件锁（`GraphStore.withLock`
   已存在，扩展成覆盖整个读改写周期），然后才考虑同题多 Execute 并行。
   没有锁之前**不要**开并行。
6. **Decide 触发策略**：现在只要有可派发 step 就一直 Execute，长队列时 Decide 被饿死。
   建议：每 K 个 Execute 后（或出现 `finding`/新 fact 时）插一次 Decide，
   但用图签名去重，避免空转。
7. **deferred 的跨轮重试**：给 meta 加 `attempts` 与 `nextRetryAt`，driver 下一 visit
   按指数退避重试；连续失败 N 次才真正 `deferred`。
8. **活动级评测台**：用假模型（或录制的 provider）跑固定题集，统计每题
   活动数 / 墙钟 / token / 成功 flag；这是调 prompt 和预算的前提。
9. **Decide 彻底隔离**：为 decide 活动提供独立 profile/patch，在组合层不挂
   bash/fs/net 工具（现在只是 guard 拒绝），同时把 schema 上下文再压短。

### P2 — 体验与维护

10. **Client 显示活动信息**：`/fgs/state` 已有 `activity / activityRunId / activityBlocked /
    lastCommit`，黑板条可以显示「当前活动 + runId + 上一轮结果」，实战时更好判断卡在哪。
11. **活动 prompt 打磨**：`prompts/decide.system.md` / `execute.system.md` 还是为旧单会话写的，
    建议按「短、单活动、结束信号」重写，并保持 0 Skill / 0 RAG / 0 MCP。
12. **修 `fake_llm.py`**：让它在收到 tool 结果后返回文本，就能把真实 host E2E 变成离线回归。
13. **文档同步**：`CONTRACT.md` 补一节「活动 run 协议」；`README` 的插件页截图/名称更新为
    `@local/fgs-v5-dsh`。

### 不要做

- 不要重写 kernel（GraphStore/Controller/ops/hooks/FLAG 门）——它已经被 249 条测试锁住。
- 不要在没加跨进程锁时开并行写图。
- 不要把活动模式做成默认（GUI 单会话路径仍有用；活动模式只由 env 驱动）。
